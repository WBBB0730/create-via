# 0001 用通用的建项目工具替代 GitHub 模板功能

## 背景

**GitHub 模板功能**建出的仓库带不上 Git LFS 文件，而游戏这类模板的图片、音频、模型都由 LFS 管理。原来的绕法是在模板的 `.gitattributes` 里放一个「模板开关」，用模板建好仓库后，再照 README 手动打开 LFS。步骤多，也容易漏。

## 决定

做一个通用的命令行工具：`npx create-via@latest <模板仓库> [项目名]`。

- **模板仓库**作为参数传入，工具本身不认识任何具体的模板。
- 只做到本地为止：拉取最新文件、`git init`、做一次**初始提交**。不建远程仓库，也不依赖 gh。

## 理由

- 和 giget 一样把仓库当参数，工具的逻辑就跟具体模板无关。任何模板去掉自己的模板开关就能用，工具不用改。
- 使用者要的终点就是本地有一个提交。建远程仓库得依赖 gh 或 GitHub 令牌，而不是每个人都装了 gh。

## 后果

- 远程仓库由使用者自己建，然后推送。
- 模板仓库不再需要专为 GitHub 模板功能准备的开关，二进制文件直接交给 LFS 管理即可。

## 被否的方案

- **GitHub 模板功能加模板开关**：就是要替代的现状。
- **giget 加几条手敲的 git 命令**：giget 能拉取，但 `git init` 和提交要使用者自己敲，步骤多。
- **gitpick**：能做到，但是小众库。
- **Copier**：要先装 uv，运行时要加 `--trust`，模板里还得多一个 `copier.yml`。
- **只为某一个模板做专用包**：工具逻辑跟具体模板无关，没有理由写死。
